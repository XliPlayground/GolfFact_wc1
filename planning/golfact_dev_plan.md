# 高尔夫室外打位微信小程序预约系统——开发计划

## 1. 项目定位与目标

为朋友的高尔夫室外打位门店（当前 2 个打位）打造一款微信小程序，覆盖：
- 客户自助预约打位 / 培训
- 门店小店吧商品展示
- 教练展示
- 管理员后台维护用户、会员时长、等级、积分、下场活动和会员赛

所有支付均走线下，小程序内不做在线支付。

此外新增需求包括：爽约管理、教学/自助时段区分、自助时段门禁密码、时段折扣、下场记分卡、教练账单对账等。

## 3. 技术方案选项

### 方案 A：微信小程序原生 + 微信云开发（CloudBase）—— 推荐

- **前端**：微信小程序原生框架（WXML + WXSS + JS）
- **后端/数据库**：微信云开发（云函数 + 云数据库 + 云存储）
- **优势**：
  - 无需购买服务器和域名，零运维
  - 微信登录、手机号授权一体化
  - 适合小规模门店，成本低
  - 部署简单，后续维护容易
- **劣势**：
  - 云开发有调用量和存储限制（免费额度通常够用，超出后按量付费）
  - 数据导出/复杂查询不如传统数据库灵活

### 方案 B：uni-app + 微信云开发

- **前端**：uni-app（Vue 语法）
- **后端/数据库**：微信云开发
- **优势**：
  - 一套代码可同时打包成微信小程序、H5、App（未来扩展方便）
  - Vue 语法上手快，生态组件丰富
- **劣势**：
  - 相比原生小程序，包体积略大，部分微信新特性支持有延迟

### 方案 C：Taro / uni-app + Node.js 后端 + MySQL

- **前端**：Taro 3（React）或 uni-app
- **后端**：Node.js + Express / Nest.js
- **数据库**：MySQL / PostgreSQL
- **部署**：云服务器 + 域名 + HTTPS
- **优势**：
  - 完全自主可控，适合业务复杂、后续扩展多
  - 数据报表、复杂查询能力强
- **劣势**：
  - 需要服务器、域名、备案、SSL 证书
  - 运维成本和开发周期更长

### 推荐选择

**方案 A（微信小程序原生 + 微信云开发）**，原因：
- 门店目前只有 2 个打位，业务量小
- 无在线支付，业务逻辑相对简单
- 预算和开发周期都应尽量短
- 微信生态原生体验最好

若未来需要扩展到 H5 或 App，可再考虑方案 B 重构前台。

## 5. 页面结构

1. **首页** (`pages/index/index`)
   - 门店信息、快捷入口（预约、小店吧、教练、活动、赛事）、公告
   - 当前用户秋の认证统计与最近 10 场比赛总杆数折线图

   - 选择普通打位预约 / 培训预约

## 6. 开发阶段与里程碑

### 第一阶段：基础框架与核心预约（约 3 周）

目标：让管理员能用起来，用户能注册、预约。

1. 小程序项目搭建、云开发环境配置
2. 管理员登录、角色区分
3. 用户管理：注册用户信息查看、剩余小时数、会员等级、爽约次数维护
4. 打位与时段设置（支持教学/自助类型、折扣）
5. 爽约规则配置
6. 预约管理：预约列表/日历、防止冲突、取消与爽约判定
7. 前台用户微信登录、个人信息页
8. 前台打位预约（教学/自助）、培训预约、我的预约

### 第二阶段：充值闭环、权益卡与自助门禁（约 2 周）

1. 老板后台直接给用户充时，设置到期日
2. 充时卡模板：销售卡、体验卡、福利加油包、自定义卡
3. 批量生成实体卡：卡号、长兑换码 token、二维码路径；支持预制空卡
4. 扫码激活实体卡：读取卡号后自动带出模板信息，老板只需确认
5. 连号批量激活：输入起始卡号 + 数量（如 10 张）+ 模板，一次激活递增卡号
6. 客户扫码兑换：校验长兑换码 token，兑换成功后卡片立即失效
7. 体验卡限制：支持每个用户生命周期仅一次、仅新用户、或不限制
8. 福利卡限制：支持每人一次、周期一次、指定会员等级、或不限制
9. 小店吧商品展示、商品分类管理、教练展示、教练管理后台
10. 自助预约门禁密码策略与显示，时段折扣在预约时的展示

### 第三阶段：下场活动、记分卡与积分（约 2-3 周）

1. 下场活动发布与报名
2. 会员赛发布
3. 下场记分卡：逐洞 0-10 滚轮记录、自动草稿保存、最终选择球场后提交
4. 比赛成绩审核与积分生成
5. 训练时长积分自动统计
6. 积分排名展示

### 第四阶段：教练账单与收尾（约 1-2 周）

1. 教练端登录与日程查看
2. 教练账单生成（周期汇总）
3. 账单“待讨薪”/“已拨付”状态流转
4. 后台教练账单管理

### 第五阶段：测试、优化与上线（约 1 周）

1. 真机测试、权限测试（用户/教练/管理员三端）
2. UI 美化、异常提示优化
3. 提交微信小程序审核
4. 上线后管理员与教练培训

**总周期预估：9-11 周**（1 人兼职开发，每周投入 15-20 小时）

## 7. 需要提前确认的事项

1. **小程序主体**：用个人、个体工商户还是企业资质？影响认证能力（如获取手机号、部分接口）。
2. **手机号授权**：是否需要真实手机号？若需要，必须完成微信认证并接入 `getPhoneNumber`。
3. **会员等级规则**：希望按累计充值金额、累计预约次数、还是累计训练时长划分？
4. **积分规则**：比赛成绩如何换算积分？训练时长如何换算积分？是否需要不同权重？
5. **打位营业时间**：每天可预约时段是什么？每个时段多长（如 1 小时/半小时）？
6. **爽约/完成规则**（已确认：后台可配置，支持按用户单独设置）：预约时先冻结/扣除基础时长；预约结束后老板有 48 小时确认窗口，可点完成或爽约；48 小时未处理按“无异议完成”正常结算；爽约默认按 1.5 倍时长结算，后台可改。
7. **门禁密码策略**（已确认：后台统一设置，所有自助用户显示同一密码，管理员人工定时更换，预留门锁联动扩展）。
8. **折扣规则**（已确认：后台可配置，默认无折扣，支持分时段/日期设置）。
9. **教练结算**（已确认：支持全局统一价 + 按教练单独覆盖，账单周期周/月/自定义）。
10. **记分卡规则**（已确认：每洞记录打击杆数、推球杆数、罚杆，均用 0-10 滚轮选择；每次选择自动保存草稿，避免丢失；保存记分卡时选择球场名称，GPS 球场识别预留）。
11. **设计风格**（已确认：简约绿色主题，主题色默认 `#22c55e`）。
12. **营业时段**（已确认：管理员后台调整，默认 05:00-24:00，时段粒度 30 分钟）。
13. **预约规则**（已确认：每次至少 2 段 = 1 小时，每日最多预约小时数后台可调）。

## 9. 风险与建议

- **预约冲突**：2 个打位资源紧张，必须做严格时段冲突校验，建议后台可手动锁定时段。
- **爽约判定**：取消时间以客户端提交时间为准，需考虑网络延迟，建议以服务器时间为准并保留操作日志。
- **门禁密码安全**：当前采用后台统一密码，所有自助用户共用。存在泄露风险，建议定期更换并在后台设置更新提醒；未来对接智能门锁后可改为动态密码或一次性密码。
- **教练账单争议**：账单金额 = 课时数 × 课时单价，需在预约确认时即固定单价，避免后期调价引发争议。
- **下场记分卡真实性**：客户自填成绩存在作弊或误填风险，会员赛成绩建议后台审核后再计入积分。
- **线下支付对账**：充值、比赛报名费、教练课时费都走线下，建议后台增加“充值记录”“缴费备注”“账单拨付备注”功能，方便对账。
- **数据安全**：管理员/教练密码必须加盐哈希存储；用户敏感信息（电话、门禁密码）在云数据库中设置权限。
- **审核风险**：小程序不含在线支付通常审核较顺畅，但避免使用“商城”“购买”等强电商词汇，可强调“展示/到店支付”。
- **后续扩展**：若未来增加更多打位、分店或在线支付，建议第二阶段迁移到方案 C。
